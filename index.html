The problem

Chat models answer.
Your workflow needs a decision.

Ask a chat model to route a ticket or approve a refund and you get three problems before you get an answer.

01 / PARSING

Prose you have to parse.

A yes, a category or a rating comes back wrapped in sentences or loosely shaped JSON. So you add schema prompts, validators and retries, and the workflow still stops when one reply is shaped differently.

02 / CONFIDENCE

A confidence that is not a probability.

Ask the model how sure it is and it writes a number. Nothing makes that number add up across the options or hold steady between calls, so you cannot set a threshold and trust it.

03 / CONTROL

An API you do not run.

Each decision sends internal state to someone else's endpoint. You inherit their latency, their limits and their data terms for a call that should stay inside your own process.

How it works

Three steps from
situation to probabilities.

Describe the state, ask independent questions, act on the numbers. One request can carry up to 128 questions, and each is scored on its own.

01 / DESCRIBE

Send the state.

Give Vej the situation as text or JSON: a message, an account record, a document.

02 / ASK

Ask independent questions.

Choice picks among outcomes you name and describe. Noul says whether a statement holds. Score rates the state against rubric levels you write. Questions do not see each other.

03 / ACT

Apply your policy.

Each answer is a distribution that sums to one. Your code sets the thresholds, gates the tool call or asks for more information. Vej never executes anything.

REQUEST · examples/decisions.json

{
  "state": {
    "message": "Please cancel my subscription. I have not provided an account ID.",
    "account_id": null,
    "account_verified": false
  },
  "questions": {
    "route": {
      "type": "choice",
      "question": "Which action best matches the request?",
      "options": {
        "cancel_subscription": "Cancel an existing subscription",
        "lookup_invoice": "Retrieve a billing invoice",
        "none": "Neither offered action applies"
      }
    },
    "can_execute": {
      "type": "noul",
      "statement": "The account is verified and its ID is available."
    },
    "completeness": {
      "type": "score",
      "question": "How complete is the information needed to execute cancellation?",
      "levels": [
        "The account ID and account verification are both missing",
        "Exactly one of account ID or account verification is missing",
        "The account ID is available and the account is verified"
      ]
    }
  }
}

Evaluation / 26 September 2026

Tested on 14,286 held-out decisions.
Compared with Jev on the same rows.

HelpSteer1 ratings and Schema-Guided Dialogue decisions, frozen before the final run. Both sources also contribute training data, so this measures transfer within known sources, not an unseen test.

Exact accuracy of Vej alpha2 and hosted Jev 1.13 on the same 14,286 test decisions
Task Decisions Vej alpha2 Hosted Jev 1.13¹
Choice · pick an outcome 6,197 89.22% 83.07%
Noul · assess a statement 3,089 91.71% 93.65%
Score · exact rubric level 5,000 51.62% 44.20%

¹ Jev is TypeSafe's hosted decision model. Its column uses the documented post-launch rounding adjustment; counting the 98 strict failures as wrong gives 71.45%. This is one fixed test, not Jev's own benchmark, and speed and cost were not compared.

Score needs more work.

51.62% exact-level accuracy against 48.44% for a post-hoc test-majority control. That control uses the test labels, so rubric scoring is the clear next problem.

Tool readiness is not permission.

A separate development suite passed 30 of 48 harder tool cases, with nine wrong calls among 31 "ready" predictions. Keep execution behind your own checks.

Where it fits

Four places a distribution
beats a paragraph.

Each pattern keeps the judgement in the model and the rule in your code.

Route a request.

A support message could mean billing, security or cancellation. Vej returns a probability for each route; clear cases dispatch, split cases go to a person.

Gate a tool call.

A refund call needs a verified account ID. Ask Noul whether the requirement holds and block the call when the answer is a confident no.

Score a reply against a rubric.

You want every agent answer graded on completeness levels you wrote. Score returns a distribution over the levels, and your code turns it into an expected grade.

Decide when to escalate.

A workflow hits conflicting instructions. Ask Choice to weigh retry, fallback and human handoff, then apply the threshold your policy demands.

Questions

Straight answers.

What Vej returns, how it compares, and what it does not claim.

What does Vej return?
A probability for each outcome you define, within each independent question. Choice picks among named outcomes, Noul assesses whether a statement holds, and Score rates described rubric levels; the expected position is computed in your code.
How is Vej different from Jev?
Jev is TypeSafe's hosted decision model and API. Vej offers the same three question types, Choice, Noul and Score, as a 2B model you run on your own hardware, with Apache-2.0 code. On the same 14,286-decision test Vej scored 76.60% and hosted Jev 1.13 scored 71.76%; Jev led on Noul. Speed and cost were not compared.
Can I run Vej on my own hardware?
Yes. Inference runs locally through Vej's native loader on a CUDA or ROCm GPU, or on CPU when speed does not matter. The checkpoint is about 3.6 GiB, and it was trained and evaluated on one 16 GB card.
Can I get the weights?
Not publicly yet. The checkpoint is published privately on Hugging Face as Kennes/vej-qwen-2b-alpha2 for authorized account members. Public open-weight distribution is an ambition, not current availability.
Is Vej open source?
Vej's code and model adaptations are Apache-2.0. The development repository and the weights are private during the alpha. The Qwen base model and the original datasets keep their own terms.
How was Vej evaluated?
On 14,286 held-out decisions from HelpSteer1 and Schema-Guided Dialogue, run on 26 September 2026. Vej reached 76.60% exact accuracy overall: 89.22% on Choice, 91.71% on Noul and 51.62% on Score. Hosted Jev 1.13 reached 71.76% on the same rows with the documented rounding adjustment.
Is Vej production-ready?
No. Vej is a text-only research alpha. Score accuracy and tool diagnostics remain weak, confidence is not calibrated, and probabilities are not permission to act. Keep execution behind your own policy checks.
What does "Noul" mean?
Noul is Vej's name for the assess-a-statement question type. It returns probabilities for true and false. It is an intentional product term, not a spelling mistake.
