How it works

One request carries up to 128 independent questions, each scored on its own.

01 / DESCRIBE

Send the state.

Pass the situation as text or JSON: a message, record, or document.

02 / ASK

Ask independent questions.

Choice picks among named options. Noul tests whether a statement holds. Score evaluates rubric levels. Questions do not see each other.

03 / ACT

Apply your policy.

Each answer sums to one. Your code sets thresholds and gates actions. Vej never executes anything.

REQUEST

{
  "state": {
    "message": "Please cancel my subscription. I have not provided an account ID.",
    "account_id": null,
    "account_verified": false
  },
  "questions": {
    "route": {
      "type": "choice",
      "question": "Which action best matches the request?",
      "options": {
        "cancel_subscription": "Cancel an existing subscription",
        "lookup_invoice": "Retrieve a billing invoice",
        "none": "Neither offered action applies"
      }
    },
    "can_execute": {
      "type": "noul",
      "statement": "The account is verified and its ID is available."
    },
    "completeness": {
      "type": "score",
      "question": "How complete is the information needed to execute cancellation?",
      "levels": [
        "The account ID and account verification are both missing",
        "Exactly one of account ID or account verification is missing",
        "The account ID is available and the account is verified"
      ]
    }
  }
}

Uses

Route a request.

Pea returns probabilities for billing, security and cancellation. Your code can route clear requests and send uncertain requests to a person.

Gate a tool call.

A refund requires a verified account ID. Use Noul to assess this condition. Your code must check the account before it issues a refund.

Score a reply against a rubric.

Grade answers against your rubric. Score returns a distribution over levels, and your code computes the expected position.

Decide when to escalate.

Use Choice to compare a retry, an alternative action and a review by a person. Your code applies the decision threshold.

Questions

Which models can I use?
Pea (2B) is available for decisions in limited hosted early access, with Pea 1 weights by approved Hugging Face request. Pea extraction is live in hosted Beta at /v1beta/extract (extraction weights are private). Pepper and Pumpkin are in development and tested privately with companies; neither is publicly available.
What is Pea extraction?
Pea extraction is a hosted capability of Pea. It reads a document and extracts developer-defined fields by predicting exact Unicode evidence spans. It uses prefill only—no text generation and no autoregressive decoding. Each answer cites character offsets in your text, and typed values are parsed from that evidence. When a field is probably absent, its value is null.
What context size can I use?
Pea decisions and Pea Pod extraction support 96K (98,304) tokens per row in realtime and 2K (2,048) tokens per row in batch. Each complete row includes the state or document, instructions, and candidate or field. Over-limit rows are rejected, never truncated. See the model limits.
What does Pea return?
A probability for each outcome you define. Choice weighs named options, Noul assesses statements, and Score rates rubric levels. Your code decides what happens next.
Can I run Pea on my own hardware?
Yes. Download Pea 1 from https://huggingface.co/ItsVej/pea-1 after your access request is approved. The native loader also needs the private Vej source. Supported inference uses the native loader on your GPU; CPU execution is a slower fallback. The model card includes setup instructions and current limits.
Is there a hosted API?
Yes. The hosted API is live at api.itsvej.com: Pea for decisions on /v1/predict, and Pea extraction on /v1beta/extract (Beta). Text only; image input is refused. Create a console account and wait for manual approval before using the API. Capacity is limited, with no uptime guarantee yet.
How should I use Pea’s probabilities?
Set thresholds using examples from your own workflow, and pair tool actions with independent policy checks. The published evaluation reports exact accuracy across 14,286 decisions at temperature 1. The hosted API uses temperature 1.334. A stated probability is not a guaranteed frequency.
