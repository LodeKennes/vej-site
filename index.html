How it works

One request carries up to 128 independent questions, each scored on its own.

01 / DESCRIBE

Send the state.

Pass the situation as text or JSON: a message, record, or document.

02 / ASK

Ask independent questions.

Choice picks among named options. Noul tests whether a statement holds. Score evaluates rubric levels. Questions do not see each other.

03 / ACT

Apply your policy.

Each answer sums to one. Your code sets thresholds and gates actions. Vej never executes anything.

REQUEST · examples/decisions.json

{
  "state": {
    "message": "Please cancel my subscription. I have not provided an account ID.",
    "account_id": null,
    "account_verified": false
  },
  "questions": {
    "route": {
      "type": "choice",
      "question": "Which action best matches the request?",
      "options": {
        "cancel_subscription": "Cancel an existing subscription",
        "lookup_invoice": "Retrieve a billing invoice",
        "none": "Neither offered action applies"
      }
    },
    "can_execute": {
      "type": "noul",
      "statement": "The account is verified and its ID is available."
    },
    "completeness": {
      "type": "score",
      "question": "How complete is the information needed to execute cancellation?",
      "levels": [
        "The account ID and account verification are both missing",
        "Exactly one of account ID or account verification is missing",
        "The account ID is available and the account is verified"
      ]
    }
  }
}

Uses

Route a request.

Pea returns probabilities for billing, security and cancellation. Your code can route clear requests and send uncertain requests to a person.

Gate a tool call.

A refund requires a verified account ID. Use Noul to assess this condition. Your code must check the account before it issues a refund.

Score a reply against a rubric.

Grade answers against your rubric. Score returns a distribution over levels, and your code computes the expected position.

Decide when to escalate.

Use Choice to compare a retry, an alternative action and a review by a person. Your code applies the decision threshold.

Development

Run Pea through the CLI, a local HTTP server or the Jev and Cloudflare Clef SDK formats. The vLLM export is experimental. It has not passed the checks for numerical accuracy and contract parity. See local inference.

Pea research

We paused Noul development on 9 October. No candidate improved its development result and passed the checks for the other tasks. Pea and its published results have not changed.

Hosted API

We are building an EU-hosted API for Choice, Noul and Score. Plans include Jev and Clef formats and batch jobs with your EU storage. We plan to keep request content out of our storage. We must verify this before launch. Self-hosting will remain available. Draft data processing agreement.

Questions

Which models can I use?
Pea is the current research alpha, with private checkpoint access by request. Pepper and Pumpkin are in development and tested privately with companies; neither is publicly available.
What does Pea return?
A probability for each outcome you define. Choice weighs named options, Noul assesses statements, and Score rates rubric levels. Your code decides what happens next.
Can I run Pea on my own hardware?
Yes, with authorised checkpoint and source access. Supported inference uses the native loader on your GPU; CPU execution is a slower fallback. The model card includes setup instructions and current limits.
Is there a hosted API?
Not today. An EU-hosted option is in development. The public website does not run inference or accept model inputs.
Is Pea production-ready?
Pea is a research alpha. Score accuracy and tool diagnostics remain weak. Confidence is not calibrated. The published evaluation is one test. It does not guarantee general performance.
