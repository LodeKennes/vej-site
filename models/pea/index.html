Run Pea locally

Download ItsVej/pea-1 after your Hugging Face access request is approved. The native checkpoint is the checkpoint directory in that download. Python 3.12 to 3.14 is supported. vej predict still needs the private Vej source and its locked dependencies. 

HF_HUB_OFFLINE=1 python -m vej predict \
  examples/decisions.json --checkpoint /path/to/download/checkpoint --device cpu

CPU execution is a functional fallback and can be slow. The backbone remains BF16. Disabling autocast does not convert it to FP32. For compatible CUDA or ROCm environments, follow the supplied installation instructions in your GPU environment, then execute: 

HF_HUB_OFFLINE=1 python -m vej predict examples/decisions.json \
  --checkpoint /path/to/download/checkpoint --device cuda \
  --precision bfloat16 --candidate-batch-size 4

Local HTTP and SDKs

vej serve --backend local --checkpoint /path/to/download/checkpoint --device cuda

The server binds to 127.0.0.1 by default, without authentication. Keep it local. It exposes POST /v1/predict, /healthz, /readyz and /metrics; native responses include usage.processed_tokens.

The official TypeSafe (Jev) Python SDK uses POST /v1/systemone. Cloudflare Clef uses POST /client/v4/accounts/{account_id}/ai/run/@cf/cloudflare/{clef|clef-flash}. Both text wire formats work on local and experimental vLLM backends.

The serving commands, SDK adapters, exporter and context override require the current private Vej source with its locked model runtime dependencies. The prediction commands above use that source with the downloaded checkpoint directory.

Serving export

The root of ItsVej/pea-1 is a classification export for vLLM ≥ 0.27. vllm serve ItsVej/pea-1 needs no extra flags. The native checkpoint under checkpoint/ remains the reference loader.

Architecture

Pea uses a pretrained 2B text backbone. Vej freezes its base BF16 parameters and trains rank-16 LoRA adapters alongside a custom FP32 scalar decision head. There is no vocabulary projection head or token generator in this text-only checkpoint. Pea’s released checkpoint is designed and evaluated for text decisions.

State + question + outcome→Scalar score

State, question, and candidate text are concatenated and passed through the model to produce a scalar score. The model normalises candidate scores into probabilities for each independent question. Application code calculates zero-based rubric expectations.

Usage guidance

The final test recorded 76.60% exact accuracy across 14,286 decisions: 89.22% on Choice, 91.71% on Noul and 51.62% on Score. Those figures use temperature 1. The hosted runtime applies temperature 1.334. Validate thresholds on your own workflow and keep independent policy checks around consequential actions. See the full evaluation for calibration, tool diagnostics and the same-test comparison with hosted Jev.

Vej code and model adaptations use Apache-2.0, while upstream base assets and training datasets retain their respective terms. See licences and attribution.

Hosted runtime

The hosted API is live in limited early access, by request. It serves Pea’s native reference runtime for text only; image input is refused. Hosted Choice, Noul and Score probabilities use temperature 1.334, fitted on 2,026 held-out calibration decisions and checked on 1,016 further decisions. That scale does not make a stated probability a guaranteed frequency on a new workflow. Capacity is limited, with no uptime guarantee yet. Published evaluations describe the native checkpoint at temperature 1, not a separate hosted evaluation.

If hosted Pea moves to vLLM, probabilities may differ from the native reference by up to about 0.05 (five percentage points) in development checks. Served-runtime temperature fitting and separate held-out verification would be needed. This development tolerance is not a claim of native equivalence or a universal error bound.
