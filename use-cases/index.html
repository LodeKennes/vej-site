Use cases

Pea returns a probability for a question that you write. Choice selects one named option. Noul gives a probability that a statement is true. Score rates a list of levels. We propose 11 new APIs. Each API has three use cases and a step-by-step example. Some examples use Choice or Noul. The others use estimates, evidence links, record selection, or rankings.

Status: proposed. None of these APIs is available. The formats can change. We did not measure the numbers in the examples.

1. Target error rate

Set a target error rate with labeled examples. Pea returns an answer or does not answer. A person reviews each case without an answer.

SOFTWARE ENGINEERING

API change review

A release engineer sends a code change and an error target. Pea returns an answer or does not answer. The engineer decides whether to approve the change.

CUSTOMER SUPPORT & E-COMMERCE

Refund email queue

A shop sends a refund email and an error target. Pea returns a category or does not answer. An agent decides each refund from the result.

HEALTHCARE ADMINISTRATION

Hospital claim categories

A hospital clerk sends a claim record and an error target. Pea returns an admission category or does not answer. A coder checks the result before claim submission.

Send a text and its sources. Pea links each claim to source sentences and returns probabilities for support, contradiction, or absent evidence.

SOFTWARE ENGINEERING

Release note evidence

A release engineer sends release notes and merged change titles. Pea returns source links for each claim. The engineer corrects claims without support.

CUSTOMER SUPPORT & E-COMMERCE

Return policy answers

A support agent sends a draft reply and the return policy. Pea returns evidence for each claim. The agent corrects the reply before the customer receives it.

EDUCATION

Course guide summaries

A course coordinator sends a course summary and the approved guide. Pea returns source links and contradictions. The coordinator corrects the summary before publication.

3. Number with a range

Ask for a quantity. You set the low limit and the high limit. Pea returns a middle value, a low estimate, and a high estimate.

SOFTWARE ENGINEERING

Code review schedule

A team lead sends the change size and the review queue. Pea returns a middle value, a low estimate, and a high estimate for the review hours. The lead uses the values to plan reviewer time.

LOGISTICS & SUPPLY CHAIN

Supplier delay estimates

A planner sends a supplier email about a late delivery. Pea returns a middle value, a low estimate, and a high estimate for delay days. The planner checks the estimates before any order date changes.

BANKING & INSURANCE

Repair estimate review

A claims agent sends a repair report. Pea returns a middle value, a low estimate, and a high estimate for the cost. An assessor checks the report and decides the payment amount.

Send a document. Pea answers your questions for each sentence, paragraph, or line, with the full document as context.

SOFTWARE ENGINEERING

Defect probability by section

A developer sends a code change in sections. Pea returns a defect probability for each section. The developer checks each result before approval.

MANUFACTURING

PUBLIC SECTOR

Permit file sections

A clerk sends a permit application in sections. Pea returns a probability that a section is a site plan, an identity document, or a payment receipt. The clerk checks each result. The clerk makes each permit decision.

5. Watch a conversation

Create a conversation state with questions and alert thresholds. Add each message. Pea returns revised answers and any alert after each message.

SOFTWARE ENGINEERING

Incident channel updates

An incident bot sends each new chat message. Pea returns the probability that the team has identified a cause. An engineer confirms the cause before the status page changes.

BANKING & INSURANCE

Personal advice in a customer chat

A bank sends each new message from the customer and from the agent. Pea returns a personal advice probability after each message. Pea sends an alert to a supervisor when the probability is above the threshold. The supervisor reads the exchange. The supervisor decides the response.

SECURITY OPERATIONS

Suspicious session events

A security tool sends session events after a rule alert. Pea returns an account abuse probability and alerts an analyst. The analyst and current security controls decide each account restriction.

6. Use your corrections

Send a correction after a person checks an answer. A scheduled model update uses the correction. Later answers show your model version.

SOFTWARE ENGINEERING

False defect reports

A developer sends a code section. Pea returns a defect probability. The reviewer corrects a wrong label. The reviewer checks later answers after the scheduled update.

HR & RECRUITING

Applicant document labels

A recruiter sends an applicant document. Pea returns a document type. The recruiter corrects an incorrect label for the scheduled update and keeps each employment decision.

MEDIA & CONTENT MODERATION

Local policy examples

A moderator sends a reported post. Pea returns a policy breach probability. Two moderators confirm a correction for the scheduled update and keep each enforcement decision.

7. If so, then…

Ask a first question and a conditional question. Pea returns the conditional probability and its product with the first outcome probability.

SOFTWARE ENGINEERING

API break and migration notice

A release engineer sends a code change. Pea returns API break and conditional migration probabilities. The engineer checks the combined result before a release notice changes.

CUSTOMER SUPPORT & E-COMMERCE

Refund request reasons

A shop sends a customer email. Pea returns the refund intent, conditional reason, and combined probabilities. An agent checks the charge records and decides each refund.

BANKING & INSURANCE

Water damage documents

A claims agent sends a damage report. Pea returns water damage and conditional invoice probabilities. The agent checks the file and decides which documents to request.

9. Step-by-step checks

Define each check and each condition. Pea returns each result. Pea asks for a document when a condition requires it. Pea continues after a person supplies the document.

SOFTWARE ENGINEERING

Release document checks

A release engineer sends a change and the release notes. Pea returns an API-break probability for the change. Pea returns a probability that each note has a source. The engineer supplies a missing source. The engineer decides whether to approve the release.

PUBLIC SECTOR

Application document requests

A caseworker sends an application document list. Pea returns document check results and requests an absent payslip. The caseworker supplies it and keeps each eligibility decision.

HEALTHCARE ADMINISTRATION

Claim document checks

A hospital clerk sends a claim file and its form text. Pea returns document and code consistency check results. The clerk supplies absent documents and checks the claim before submission.

10. Rank with probabilities

Send candidates and a question. Pea returns a first-place probability and a probability that the candidate is in the top group you set.

SOFTWARE ENGINEERING

Outage cause review

An incident tool sends changes made before an outage. Pea returns cause rank probabilities. An engineer examines the first two candidates before any service change.

MANUFACTURING

Fault code review

A technician sends fault codes from a stopped production line. Pea returns cause rank probabilities. The technician examines the first three candidates and follows the approved repair procedure.

MEDIA & CONTENT MODERATION

Reported post queue

A supervisor sends a batch of reported posts. Pea returns review priority rank probabilities. Moderators examine the first ten candidates and keep each enforcement decision.
