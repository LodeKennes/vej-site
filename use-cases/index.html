Use cases

Explore how probability outputs can help route requests, review documents and support decisions. These 11 workflows show industry examples, step-by-step interactions and API previews.

Limited hosted early access. These Beta workflows are live on /v1beta with Pea’s native reference runtime. Create your account for manual approval, then sign in to the console. Pea only, text only; image input is refused. Hosted Choice, Noul and Score probabilities use temperature 1.334. Capacity is limited, with no uptime guarantee yet. Choice, Noul and Score on /v1/predict, plus Jev and Cloudflare-compatible formats, are live on GA /v1. Beta availability does not establish quality or promotion to /v1. Example values are illustrative, and formats may change.

Live Beta modes: risk targets with calibrations, alignments, estimate, annotate, states, feedback, given, bind, flows, effort (standard only) and rankings (quality gate failed). States require organization retention opt-in; Vej stores the history encrypted. Batch routes exist, but running jobs requires approved EU storage hosts. Those hosts are not configured yet, so batch is not open.

1. Target error rate

Set a target error rate with labeled examples. Pea returns an answer or does not answer. A person reviews each case without an answer.

SOFTWARE ENGINEERING

API change review

A release engineer sends a code change and an error target. Pea returns an answer or does not answer. The engineer decides whether to approve the change.

CUSTOMER SUPPORT & E-COMMERCE

Refund email queue

A shop sends a refund email and an error target. Pea returns a category or does not answer. An agent decides each refund from the result.

HEALTHCARE ADMINISTRATION

Hospital claim categories

A hospital clerk sends a claim record and an error target. Pea returns an admission category or does not answer. A coder checks the result before claim submission.

Beta requirements and technical notes

Hosted Beta fits a temperature and conservative threshold from separate labeled-request cohorts (at least 500 independent risk-fit groups). Risk uses a Learn-then-Test-style simultaneous binomial procedure, distinct from classical conformal risk control. Its stated 95% confidence requires independent, identically distributed (i.i.d.) calibration groups from the deployment population; exchangeability alone is insufficient. Group fingerprints and passing customer check rows do not establish that assumption. Held-out population and target evaluation is pending; neither production promotion gate has passed. Durable fits require explicit retention consent and gateway encryption. The examples illustrate behavior, not measured quality.

POST /v1beta/calibrations · POST /v1beta/predict · risk

Send native Choice or Noul requests with their zero-based labels and independent group fingerprints. Use separate temperature-fit and risk-fit cohorts. Supply your population fingerprint; the server scores requests and fills the checkpoint and runtime binding. Scoring both cohorts bills the actual candidate-row tokens. A transient signed token is the default; no labels or documents are retained.

Risk prediction returns accept or abstain, confidence, sample size, expected answer rate, calibration identity and a drift warning. A drift warning checks the last 200 accept/abstain decisions after every decision from decision 200 onward. The bounded ring stores only booleans and a count; it cannot certify actual error without live labels. A worker restart requires a fresh fit.

For a durable fit, enable calibrations retention and set persist: true. Read or delete its ID through /v1beta/calibrations/{id}. Revocation deletes your stored fits. Both production promotion gates remain closed until held-out population and target gates pass.

2. Show the evidence

Send a statement and source documents. Pea assesses the statement independently against each source sentence and returns evidence probabilities and source offsets.

SOFTWARE ENGINEERING

Release note evidence

A release engineer sends one release note statement and merged change titles. Pea returns evidence probabilities and offsets for each source sentence. The engineer checks the statement before publication.

CUSTOMER SUPPORT & E-COMMERCE

Return policy answers

A support agent sends one statement from a draft reply and the return policy. Pea returns evidence probabilities and offsets for each policy sentence. The agent checks the statement before the customer receives it.

EDUCATION

Course guide summaries

A course coordinator sends one statement from a course summary and the approved guide. Pea returns evidence probabilities and offsets for each guide sentence. The coordinator checks the statement before publication.

Beta requirements and technical notes

Beta on the hosted API and native local server. Noul scores each source sentence independently; no span head or three-way verdict is trained. Illustrations above are not measured results. A probability above 0.5 selects evidence; no selected sentence returns no_evidence, which does not prove the statement false. No source documents are stored. Further evaluation is required before production /v1/alignments or a future hosted vLLM runtime.

POST /v1beta/alignments

Offsets are zero-based Unicode code points, end-exclusive, in the original source. Slice the caller-owned source to display text. Responses never generate quotations. Each sentence is assessed using only that sentence as state; other sources cannot change its model input. Probabilities use temperature 1.334 and are not a measured error rate for this population.

{
  "mode": "alignments",
  "input": {
    "question": "Returns are free for 30 days.",
    "sources": [{"id": "policy", "text": "Returns are free for 30 days."}]
  }
}

The response identifies the baseline, evidence or no_evidence outcome, and every scored sentence with source_id, start, end and probability. Metadata reports the base checkpoint digest and an empty parts list; usage reports all processed tokens as reread_tokens. Empty sources return no sentences and zero tokens. There is no probability distribution over an invented absent-evidence class.

3. Number with a range

Ask for a quantity. You supply ordered value bins and units. Pea returns a middle value, a low estimate, and a high estimate.

SOFTWARE ENGINEERING

Code review schedule

A team lead sends the change size and the review queue. Pea returns a middle value, a low estimate, and a high estimate for the review hours. The lead uses the values to plan reviewer time.

LOGISTICS & SUPPLY CHAIN

Supplier delay estimates

A planner sends a supplier email about a late delivery. Pea returns a middle value, a low estimate, and a high estimate for delay days. The planner checks the estimates before any order date changes.

BANKING & INSURANCE

Repair estimate review

A claims agent sends a repair report. Pea returns a middle value, a low estimate, and a high estimate for the cost. An assessor checks the report and decides the payment amount.

Beta requirements and technical notes

Beta on the hosted API and native local server. Score assesses caller-supplied value bins; code computes discrete q10, median and q90. No numeric sidecar is trained. Examples are illustrative, not measured. No tested population or calibrated coverage exists; the nominal 80% interval is not a prediction guarantee. Inputs are never retained. Further evaluation is required before production /v1/modes/predict or a future hosted vLLM runtime.

POST /v1beta/predict · estimate

{
  "mode": "estimate",
  "input": {
    "state": "A small code review with two reviewers.",
    "questions": {
      "review_hours": {
        "type": "estimate",
        "question": "How many work hours remain?",
        "unit": "hours",
        "values": [0, 3, 12, 30, 120]
      }
    }
  }
}

Supply 2–10 strictly increasing finite values within ±1e12. The response returns a median estimate and quantiles labeled 0.1, 0.5 and 0.9, with the same unit. Values remain within your supplied bins; discrete bins can yield identical lower and upper bounds. Metadata reports the base checkpoint digest, with no executed sidecars. Usage charges every processed candidate token as full re-read work. Calibration status is uncalibrated and tested population is null. Unsupported backends return 503 unsupported_mode before inference.

4. Label every part of a document

Send a document. Pea can answer your questions per sentence using caller-supplied spans, or per word, line or paragraph, with the full document as context.

SOFTWARE ENGINEERING

Defect probability by section

A developer sends a code change in sections. Pea returns a defect probability for each section. The developer checks each result before approval.

MANUFACTURING

Safety instructions in a service guide

A technician sends a machine service guide. Pea returns a safety instruction probability for each paragraph. The technician compares each result with the approved safety checklist.

PUBLIC SECTOR

Permit file sections

A clerk sends a permit application in sections. Pea returns a probability that a section is a site plan, an identity document, or a payment receipt. The clerk checks each result. The clerk makes each permit decision.

Beta requirements and technical notes

Beta on the hosted API and native local server. The whole document is read again for each candidate; cache acceleration is not qualified. No annotations are stored. Built-in segmentation accepts word, line or paragraph; sentences use caller-supplied spans. Words split on Unicode whitespace, including non-breaking spaces, with punctuation attached. Supply 1–128 segments; longer documents in word mode return a validation error, never truncation. Per-word answers have not been validated. Full re-read cost grows with words × questions × document length. Offsets count Unicode code points. Example probabilities are illustrative, not measured. Promotion to /v1/annotate remains gated. Calibration and evaluation for the alternative runtime path have not run.

5. Watch a conversation

Create a conversation state and add messages in sequence. Supply independent questions on each call. Pea re-reads the full history and returns native probabilities; your application applies alert thresholds.

SOFTWARE ENGINEERING

Incident channel updates

An incident bot sends each new chat message. Pea returns the probability that the team has identified a cause. An engineer confirms the cause before the status page changes.

BANKING & INSURANCE

Personal advice in a customer chat

A bank sends each new message from the customer and from the agent. Pea returns a personal advice probability after each message. The application sends an alert to a supervisor when the probability is above the threshold. The supervisor reads the exchange. The supervisor decides the response.

SECURITY OPERATIONS

Suspicious session events

A security tool sends session events after a rule alert. Pea returns an account abuse probability and alerts an analyst. The analyst and current security controls decide each account restriction.

Beta requirements and technical notes

Hosted Beta stores history encrypted by Vej in temporary local-directory storage. An organization administrator must explicitly opt in to states retention through PUT /v1beta/retention/states with {"enabled":true}. GET that route to check consent and pending deletion; PUT {"enabled":false} revokes access and schedules physical erasure. Sessions expire after 24 hours idle or 30 days from creation, whichever comes first. Activity refreshes only the idle deadline. Beta re-reads full history with no cache saving; native local sessions remain memory-only. History is capped at 100,000 Unicode code points, with at most 128 independent questions per call and 2,048 tokens per complete candidate row. The public request body is capped at 1 MiB. Local Beta storage allows 1 MiB of plaintext per blob and 4 MiB of ciphertext per session, within 1 GiB per organization and 256 MiB across the local backend; limits may be lower. Roundtrip qualification and independent lifecycle/security review are pending. Production /v1/states requires further runtime validation. Calibration and evaluation for the alternative runtime path have not run. Illustrative probabilities above are not measurements.

POST /v1beta/states · GET/DELETE /v1beta/states/{id} · POST /v1beta/states/{id}/events

Create at sequence 1, then submit the returned sequence as expected_seq. A stale retry returns state_sequence_conflict and never appends twice. A changed model identity returns rebuild_needed. Reset by deleting the current version and creating a new session.

{
  "mode": "states",
  "input": {"operation": "create", "expected_seq": 0, "history": "Customer: What does this fund contain?"}
}

Use the returned UUID in POST /v1beta/states/{id}/events:

{
  "mode": "states",
  "input": {
    "operation": "event",
    "expected_seq": 1,
    "event": "Agent: The fund holds technology shares.",
    "questions": {"advice": {"type": "noul", "statement": "The agent gives personal financial advice."}}
  }
}

Omit event to query the current history; full history computation is still charged and sequence advances. GET returns metadata with zero model tokens. Delete using DELETE /v1beta/states/{id}?expected_seq=2. Storage is never metered. Apply alert thresholds in your own application; this API sends no notifications.

7. If so, then…

Ask a first question and a conditional question. Pea returns the conditional probability and, when the supplied condition matches the selected first outcome, its product with the first outcome probability.

SOFTWARE ENGINEERING

API break and migration notice

A release engineer sends a code change. Pea returns API break and conditional migration probabilities. The engineer checks the combined result before a release notice changes.

CUSTOMER SUPPORT & E-COMMERCE

Refund request reasons

A shop sends a customer email. Pea returns the refund intent, conditional reason, and combined probabilities. An agent checks the charge records and decides each refund.

BANKING & INSURANCE

Water damage documents

A claims agent sends a damage report. Pea returns water damage and conditional invoice probabilities. The agent checks the file and decides which documents to request.

Beta requirements and technical notes

Hosted Beta evaluates the first event and a separate question under your explicit assumption. Both calls count toward usage. A Noul condition must be the matching boolean; a Choice condition must be the selected option name string. The result reports bound and returns product: null for other conditions. A bound product is a modeled conditional composition; it does not infer causality or event independence. Reference validation and alternative-runtime parity are pending. Production /v1/modes/predict requires these checks to pass.

Beta requirements and technical notes

First-place probabilities sum to 1; top-k inclusion probabilities sum to k. These are marginals of one listwise distribution. Beta /v1beta/rankings is live on the hosted API. 11. Select effort

Select effort for each question on POST /v1beta/predict. Standard remains the unchanged default. Fast and careful are deferred and not yet available. The use cases and story below illustrate those deferred settings; their answers are illustrative, not results available today.

SOFTWARE ENGINEERING

Illustrative · Fast and careful are deferred and not yet available.

A developer sends a code change with fast effort for style and careful effort for security. Pea returns both probabilities and effort labels. The reviewer decides whether to approve the change.

Illustrative · Careful is deferred and not yet available.

ENERGY & UTILITIES

Illustrative · Careful is deferred and not yet available.

A planner sends a maintenance note with careful effort for a safety question. Pea returns a probability that the note needs a safety review. An engineer decides the maintenance action.

Beta requirements and technical notes

Select effort independently for each primitive question on POST /v1beta/predict. Standard is available and remains the unchanged default. Fast and careful are deferred and not available. They return an explicit unavailable status with reason deferred; records 145 and 146 document owner decision 25 (2026-10-17). Pea remains the only served model.

HTTP 200 may contain both executed and unavailable questions; check each status. Standard results have status executed, effort_requested and effort_used set to standard, and the unchanged native answer. Mixed requests execute only standard questions, with no silent fallback. All-unavailable requests have zero usage, a null base digest and no executed parts. Responses report the effort actually used, executed parts and processed tokens. Request content is not retained. Hosted Beta supports standard effort only. Promotion to /v1/modes/predict remains closed until both fast and careful gates pass.
